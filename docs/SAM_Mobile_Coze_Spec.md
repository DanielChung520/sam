## 1. Coze 實作架構概觀

### 1.1 元件分工

| Coze 元件 | 在本原型中的角色 |
|-----------|----------------|
| **Bot** | 主要 UI 介面 — 使用者透過聊天框操作所有功能，Bot 回覆 Rich Cards 模擬 App 畫面 |
| **Workflow** | 後端邏輯 — OCR 名片解析、好友積分計算、排程群發佇列、賀卡生成 |
| **Knowledge Base** | 靜態資料 — 賀卡樣板庫、高 EQ 用語庫、商品 FAQ 知識庫 |
| **Variables** | 動態狀態 — 當前選取的好友、USB 連線狀態、對話 Context |
| **Plugin** | 外部連線 — LINE Messaging API 呼叫、SeaweedFS 讀寫、LLM API 轉發 |

### 1.2 使用者操作模型

使用者不離開聊天介面，透過**指令按鈕 + 表單填寫**完成所有操作：

```
[聊天框]                    [Bot 回覆]
使用者輸入:                  ┌──────────────────────┐
  /好友                       │ 📋 好友列表           │
                             │ 🔥 張三  積分 85      │
                             │ 🔥 李四  積分 62      │
                             │ 🔥 王五  積分 30      │
                             │ [下一頁] [搜尋]       │
                             └──────────────────────┘
使用者點擊「張三」           ┌──────────────────────┐
                             │ 👤 張三               │
                             │ 職稱: 業務經理        │
                             │ 積分: 85 🔥           │
                             │ 標籤: [VIP] [高意向]  │
                             │ [掃名片] [發訊息]      │
                             │ [編輯標籤] [歷史對話]  │
                             └──────────────────────┘
```

### 1.3 底部導航（模擬 Tab Bar）

Bot 回覆的每則訊息底部**固定附加**一組快速操作按鈕：

```
[💬 對話] [👥 好友] [📢 群發] [⚙️ 工作區]
```

使用者點擊任一按鈕 → Bot 切換對應頁面內容。

### 3.5 Coze Workflow：AI 擬稿

| 步驟 | 節點類型 | 動作 |
|------|---------|------|
| 1. 取得 Context | Code | 讀取 `{{變數.當前好友}}` 的職稱、積分、歷史互動 |
| 2. 查詢商品 RAG | Knowledge | 根據問題檢索商品知識庫 |
| 3. 生成回覆 | LLM | Prompt：「你是 {{好友名稱}} 的銷售助理，風格為 {{個人風格}}，根據以下 Context 生成回覆⋯」 |
| 4. 回傳草稿 | End | 回傳 `{ draft, score, tokens }` |

### 3.6 真人接管模式

使用者可在設定中切換模式：

| 模式 | 行為 |
|------|------|
| **半自動**（預設） | AI 生成草稿 → 使用者確認/修改後才發送 |
| **全自動**（高信任） | AI 自動回覆常規問題，僅複雜問題推播通知 |
| **僅離線** | 僅使用者不在線時 AI 代回 |

**Coze 實作**：User Variable `{{mode_auto_reply}}` 控制 Workflow 的 Condition 分支。

#### Coze Workflow：名片 OCR

| 步驟 | 節點類型 | 動作 |
|------|---------|------|
| 1. 接收圖片 | Plugin / Bot | 使用者上傳圖片觸發 Workflow |
| 2. OCR 辨識 | LLM (Vision) | Prompt：「請將此名片轉為 JSON 格式，包含：name, company, title, phone, email, address」 |
| 3. 結構化校驗 | Code | 驗證 JSON 完整性，缺欄位標記 `pending` |
| 4. 寫入（模擬） | Code | 追加至 `{{變數.contacts}}` 陣列 |
| 5. 生成感謝詞 | LLM | Prompt：「根據對方職稱與產業，生成一段不落俗套的感謝詞」 |
| 6. 回傳結果 | End | 回傳名片 JSON + 感謝詞草稿 |

### 4.6 標籤與積分規則

#### 積分計算公式（Workflow Code Node）

```
score = 0
score += min(message_count_7d * 2, 30)     // 近7日訊息量
score += min(reply_seconds < 300 ? 1 : 0, 20) // 平均回覆速度 <5分鐘
score += proactive_count * 5                  // 主動發訊息次數
score += min(turn_count * 3, 30)              // 對話輪數
score = clamp(score, 0, 100)
```

#### 自動標籤規則（LLM + Condition）

| 條件 | 自動標籤 |
|------|---------|
| 積分 > 80 且近 3 日有互動 | `VIP` |
| 對話中提到「預算、報價、多少錢」 | `高意向` |
| 名片職稱包含「總經理、執行長、創辦人」 | `決策者` |
| 超過 30 天無互動 | `沉睡` |

### 5.4 Coze Workflow：排程群發

| 步驟 | 節點類型 | 動作 |
|------|---------|------|
| 1. 選擇對象 | Code | 根據篩選條件查詢 `{{變數.contacts}}`，產出名單陣列 |
| 2. 產生個人化 | Iteration + LLM | 對名單中每位好友：讀取「職稱、興趣、歷史紀錄」→ LLM 生成專屬版本 |
| 3. 加入 Queue | Code | 將每則訊息加上 `scheduled_at`（間隔 3-7 分鐘亂數） |
| 4. 逐一發送 | Loop + Plugin | 依排程時間呼叫 LINE Messaging API |
| 5. 更新狀態 | Code | 每發送一則更新 `{{變數.broadcast_progress}}` |

### 5.5 LINE 群發管制因應策略

| LINE 限制 | SAM 對策 |
|-----------|---------|
| 大量相同內容易被標示為垃圾訊息 | 每則訊息使用 AI 個別產生，內容皆不相同 |
| 短時間大量發送可能遭封鎖 | 強制隨機間隔 3-7 分鐘 |
| 官方帳號 Push API 高額費用 | 使用個人 LINE 帳號 + 加密 Tunnel 發送（或用戶自備 Channel） |

## 7. 背景流程 (Background Workflows)

### 7.1 自動積分更新

| 觸發 | 流程 |
|------|------|
| 每收到一則好友訊息 | → 更新 `message_count_7d` → 重新計算積分 → 檢查標籤變動 → 回寫 `{{變數.contacts}}` |
| 每發送一則訊息 | → 同上 |
| 每日 00:00（Cron） | → 清理過期資料 → 標記沉睡客戶（30天無互動） |

### 7.2 自動感謝詞（名片掃描後）

名片寫入 USB 成功後 → 自動觸發：

```
LLM Prompt:
「{{對方職稱}} {{對方姓名}} 剛剛與你交換名片，對方的公司是 {{對方公司}}。
請根據對方的職稱與產業，生成一段150字以內、專業且不落俗套的 LINE 感謝詞與加好友招呼語。
語氣要自然，不要像罐頭訊息。」
```

### 7.3 USB 狀態心跳

| 頻率 | 動作 |
|------|------|
| 每 30 秒 | Workflow 呼叫 Plugin 檢查 USB Tunnel 狀態 |
| 狀態變更 | 更新 `{{變數.usb_status}}`，若斷線則推播通知：「🔴 USB 已拔除，資料防護啟動」 |

## 8. 變數與狀態設計

### 8.1 User Variables（Coze 使用者層級）

| 變數名 | 型態 | 初始值 | 說明 |
|--------|------|--------|------|
| `usb_status` | string | `disconnected` | `connected` / `disconnected` / `connecting` |
| `mode_auto_reply` | string | `semi` | `semi` / `full` / `offline_only` |
| `persona_style` | string | `default` | 個人對話風格描述 |
| `provider_key` | string | `""` | 遮罩顯示的 Provider Key |
| `token_balance` | number | `0` | Token 餘額（NTD） |
| `current_page` | string | `chats` | 當前頁面：`chats`/`friends`/`broadcast`/`workspace` |
| `selected_contact` | string | `""` | 當前選取的好友 ID |
| `broadcast_progress` | object | `{}` | `{ total, sent, status, eta }` |

### 8.2 Knowledge Base 結構

| KB 名稱 | 用途 | 更新頻率 |
|---------|------|---------|
| `greeting_templates` | 賀卡樣板庫 | 靜態（可追加） |
| `product_faq` | 商品 FAQ / RAG | 使用者自行上傳 |
| `high_eq_phrases` | 高 EQ 用語庫 | 靜態（可追加） |

### 8.3 資料儲存策略（Coze 限制下的模擬方案）

由於 Coze 的 Variables 有容量限制，建議：

| 資料類型 | 儲存方式 | 備註 |
|---------|---------|------|
| 好友列表（≤ 200 筆） | `{{變數.contacts}}` JSON 陣列 | 每筆含 id, name, title, score, tags |
| 對話歷史（近期） | `{{變數.recent_chats}}` JSON | 僅保留最近 20 筆 |
| 名片資料 | Knowledge Base + 檔案 | 每張名片存為 KB 條目 |
| 完整 CRM | 外部 API（後端資料庫） | 正式環境替換為 API Plugin |

## 9. Plugin / API 對接規格

### 9.1 LINE Messaging API Plugin

| 操作 | Endpoint | 用途 |
|------|----------|------|
| 發送文字訊息 | `POST /v2/bot/message/push` | 群發 / 回覆 |

| 取得使用者資料 | `GET /v2/bot/profile/{userId}` | 好友基本資料 |
| 驗證 Webhook | `POST /v2/bot/channel/webhook/test` | 連線測試 |

### 9.2 SAM Backend API Plugin（Mock）

| 操作 | Endpoint | 用途 |
|------|----------|------|
| OCR 名片 | `POST /api/v1/cards/scan` | 上傳圖片回傳 JSON |
| 好友列表 | `GET /api/v1/contacts` | 完整 CRM 資料 |
| 更新積分 | `PATCH /api/v1/contacts/:id` | 寫入新積分 |
| USB 狀態 | `GET /api/v1/usb/status` | Tunnel 心跳檢查 |
| 產生賀卡 | `POST /api/v1/greetings/generate` | 個人化賀卡生成 |

### 9.3 Coze 內建 Plugin（替代方案）

| 功能 | Coze Plugin | 備註 |
|------|------------|------|
| 圖片辨識 | GPT-4 Vision / Gemini Vision | 取代 OCR API |
| 新聞抓取 | Web Search / RSS | 取代新聞 API |
| 檔案儲存 | Google Drive / Notion | 取代 SeaweedFS（雛形） |
| 排程觸發 | Cron Trigger | 取代 Broadcast Queue |
